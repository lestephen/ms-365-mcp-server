# Consumer contract

Golden fixtures of the tool results and tool input schemas that downstream consumer code
depends on. Today the consumer is the EnviroKinetics `eki` skill library: its helpers and
hooks parse `get-download-url` tickets, upload sessions, Graph error text and draft
results, and check the input schemas of the mail draft tools.

The fixtures are generated by running the real server code, not written by hand.
[`test/consumer-contract.test.ts`](../../test/consumer-contract.test.ts) builds the MCP
server through `MicrosoftGraphServer` with the production deployment's flags (`--http`,
`--org-mode`, `--preset all`, `--discovery` with the production `--eager-tools` list, the
production `--blocked-tools` regex, `--enable-attachment-urls` and `--enable-mcp-apps`),
answers Graph requests from a mocked `fetch` with Microsoft Graph sample payloads, and
calls each tool from an in-memory MCP client. Each `results/<case>.json` therefore holds
the complete `tools/call` result exactly as an MCP client receives it.

## Layout

- `manifest.json`: contract version, the generator, and the case and schema lists.
- `results/<case-id>.json`: `case`, `tool`, `route` (`direct` or `execute-tool`, as the
  tool is reached in production), `input` (the exact arguments), `result` (the full
  `CallToolResult`), `decoded` (the first text item parsed as JSON, when it is JSON),
  `clock` and `notes`.
- `schemas/<tool>.json`: the `inputSchema` the server advertises in `tools/list`.
  `get-upload-url` and `add-mail-attachment` are not eager tools in production, so they
  are absent from the production `tools/list` (they are reached through `execute-tool`);
  their schemas come from the same flags without `--discovery`.

Output is deterministic: the clock is fixed at `2030-01-01T00:00:00Z`, ticket ids come
from a seeded generator, and minted URLs are signed with a fixed test key on the
production attachment URL base, `https://mcp.corp.envirokinetics.com`. Check `expiresAt`
and `dgx` against `clock.nowEpoch`, never against wall time.

## Consumers

`EnviroKinetics/eki` keeps a vendored copy of this directory with a `SOURCE` file naming
the fork ref it was copied from, and its contract tests read that copy. A drift workflow
there also fetches these files raw from this public repository (`main` and the latest
`v*-eki.*` tag) and runs the same tests, so a pending server change fails eki CI before
it is promoted.

## Regenerating

```sh
# Check mode (default, and what CI runs): fails if any file would change.
npx vitest run test/consumer-contract.test.ts

# Rewrite the fixtures after an intended change.
UPDATE_CONTRACTS=1 npx vitest run test/consumer-contract.test.ts
```

The files are written as `JSON.stringify(value, null, 2)` plus a newline and are excluded
from Prettier, because their exact bytes are the contract.

## The rule

**A diff under `contracts/consumer/` in a pull request is a consumer-facing change.**
Before merging it, check the eki consumers that read the changed file (search the eki
repository for the case or tool name), update them or confirm they tolerate the change,
and refresh eki's vendored copy. Additive fields are the usual case, and a consumer that
checks an exact key set breaks on them.
